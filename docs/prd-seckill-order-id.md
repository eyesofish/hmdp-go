# PRD · 抢购成功后，页面准确显示订单号

## 用户需求

已登录用户在商铺详情页抢购一张有效、有库存的券。请求受理后，只要后台尚未确认本次订单已写入 MySQL，页面就显示“订单处理中，请勿重复提交”，禁用这张券的抢购按钮，并自动查询结果。查询暂时没有结果时，页面保持处理中。

只有后台确认本次订单已写入 MySQL，页面才显示“抢购成功”和完整十进制订单号。提示中的每一位数字都必须与后台为该用户、该券保存的订单号一致。

## 验收例子

| 后台保存的订单号 | 用户在成功提示中看到的订单号 | 验收结果 |
| --- | --- | --- |
| `661639913812262913` | `661639913812262913` | 通过 |
| `661639913812262913` | `661639913812262900` | 失败，末位数字发生变化 |

## 工程交付与验收方式

仓库应包含一条可重复运行的浏览器端到端测试，并记录本地运行命令。每个 PR 的 CI 都应实际执行同一条用例，断言失败时该项检查失败。

1. 在独立测试环境准备测试用户和一张处于有效期内且有库存的测试券。每次运行使用新的用户与券组合，确保可以成功抢购。
2. 在测试环境暂缓本次订单落库。以已登录用户身份在商铺详情页点击“限时抢购”，确认请求已受理、订单表中尚无该笔记录。至少观察一次自动查询返回待确认结果，检查页面仍显示处理中、抢购按钮已禁用，且自点击以来从未出现成功提示。
3. 恢复落库，用本次用户 ID 和券 ID 查询 MySQL 的 `tb_voucher_order`，最多等待 10 秒。应恰好查到一条记录。用户无需刷新或再次点击，页面应自动显示成功提示。读取提示中的完整订单号。
4. 将数据库订单号按完整十进制文本读出，与页面提示中的订单号逐字符比较。测试数据须覆盖会在 JavaScript `Number` 转换中丢失精度的订单号，例如上表第一行。比较过程应保留双方原始数字，避免测试自身的舍入掩盖错误。

即使两个订单号最终一致，提前提示成功也判为失败。上述 10 秒仅用于限定测试等待时间。失败报告应包含用户 ID、券 ID、页面提示以及数据库查询结果，方便复核。
