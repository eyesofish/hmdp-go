# 任务 · 秒杀订单确认与订单号展示

接口示例和环境约定见[实施计划](plan.md)。按以下依赖顺序实施。

- [ ] **T1 · 建立浏览器红灯。** 在 `tests/e2e/` 搭建独立 Compose 测试环境和可释放的库存行锁，完成真实登录、页面操作、提示观察和 SQL 核对。在当前版本复现“行锁仍持有时页面已报成功”，记录该产品断言的失败信息。环境启动失败不能作为红灯依据。
- [ ] **T2 · 后端。** 在 HTTP 响应边界输出字符串订单号，实现受登录保护的确认查询。覆盖受理响应的 JSON 类型、未落库、本人已落库、他人订单、非法 ID 和数据库查询失败。依赖 T1；可与 T3 并行。
- [ ] **T3 · 前端。** 更新商铺详情页同一张券的按钮、持续提示和串行轮询；用确认响应中的字符串显示号码。覆盖重复点击、查询暂时失败、停止轮询及页面退出。依赖 T1；可与 T2 并行。
- [ ] **T4 · 联调和 PR 验收。** 合并两侧后在干净环境重跑 T1，确认首个待确认响应、库内订单数、完整订单号和页面状态都满足规格。将相同入口接入 PR CI，记录本地运行方式，并核对现有 Go 测试通过。依赖 T2、T3。
