# 功能规格 · 秒杀订单确认与订单号展示

产品验收规则已确认。需求来源为[《抢购成功后，页面准确显示订单号》](../../docs/prd-seckill-order-id.md)。

## 用户场景

已登录用户在商铺详情页抢购一张有效且有库存的券，并停留在该页面等待结果。用户需要知道请求是否仍在处理，以及抢购成功后可以凭哪个订单号核对本次购买。

| 场景 | 前提与触发条件 | 可观察的验收结果 |
| --- | --- | --- |
| 请求已受理 | 用户点击“限时抢购”，后台已受理，本次订单仍在等待写入 MySQL | 页面显示“订单处理中，请勿重复提交”，禁用该券的抢购按钮，开始自动查询。订单落库前的任何时刻都不得出现“抢购成功”，即使后台已分配订单号。 |
| 查询仍无结果 | 至少一次自动查询尚未确认本次订单已保存 | 处理提示和按钮禁用状态持续生效，页面继续自动查询。用户尝试再次点击该券时，页面不得发起第二次下单请求。 |
| 后台确认已保存 | 后台确认本次用户、本次券对应的订单已写入 MySQL | 页面自动从处理中切换为“抢购成功”，在成功提示中显示完整十进制订单号。用户无需刷新或再次点击。 |

### 订单号验收示例

当数据库保存 `661639913812262913` 时，用户必须能在成功提示中读到 `661639913812262913`。显示 `661639913812262900`、截断数字或使用科学计数法均判为失败。即使最终显示的号码完全正确，只要页面曾在落库前提示成功，时序验收仍判为失败。

## 工程验收

交付一条可重复运行的浏览器端到端用例，覆盖以上三个场景。仓库须提供本地运行命令，每个 PR 的 CI 须实际执行同一条用例，并在断言失败时返回失败。

1. 在独立测试环境准备新的用户与券组合，让已登录用户通过真实商铺详情页点击抢购。选用一个转成 JavaScript `Number` 会丢失精度的订单号，以便检测末位变化。
2. 在点击前开始观察页面提示和下单请求。测试须能暂缓本次订单写入，确认此时订单表内无对应记录，并观察至少一次待确认结果，核对处理提示、按钮状态以及实际下单请求数。
3. 恢复写入后，按测试用户 ID 和券 ID 查询 `tb_voucher_order`，最多等待 10 秒，应恰好查到一条记录。独立读取该记录的订单号，将其完整十进制文本与用户在成功提示中看到的号码逐字符比较。10 秒仅用于限制测试查库的等待时间；产品流程不得仅凭等待时间到达该值就提示失败。
4. 若超时或断言失败，报告测试用户 ID、券 ID、已观察到的页面提示和数据库查询结果，以便区分提前报成功、订单未落库和号码不一致。
